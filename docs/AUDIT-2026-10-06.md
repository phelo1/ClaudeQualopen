# Runtime recovery and paper execution audit — 6 October 2026

This audit covered the deployed Oracle instance, its scheduler/services, IBKR execution and reconciliation, data-provider handling, learning/shadow state, autonomous promotion boundaries, authenticated dashboard routes and the complete offline test suite. It is evidence of the checks below, not a guarantee that no undiscovered defect exists or that a trading strategy will be profitable.

## Findings and repairs

| Finding | Repair and validation |
| --- | --- |
| Overnight IBKR reconnect left the scheduler stuck in reconciliation; synchronous SDK requests had no default deadline. | Bound requests and fail startup on incomplete required synchronization. Separate completed-order history from live startup; a five-second history timeout retains an explicit degraded status. Tested a real history timeout and normal account synchronization. |
| Existing systemd watchdog called a command that did not exist and treated its error exit as success. | Implemented watchdog command, task-specific stall deadlines, one-minute timer, daemon-only recovery and restart cooldown. Installed the corrected unit and verified successful execution. Unit tests exercise recovery/cooldown/admin-stop behavior; no deliberate production freeze was introduced. |
| Completed OCO legs share a reference tag, making tag-based matching ambiguous. Broker history also expires. | Prefer account/client-scoped permanent execution identities. Persist actual broker callbacks and commissions; restore them on reconnect. Regression tests cover ambiguous tags, unavailable history, immutable SDK execution objects and missing commission callbacks. |
| COHU and INTR exits were missing from the application journal. | Recovered original broker events from retained service logs, with an allowlisted parser. Reconciliation closed both records using actual quantities/prices, preserving provenance. No synthetic fills were inserted. |
| Optional AI services repeatedly returned payment/quota/service errors or timed out. | Shared credential-specific cooldowns bound repeated attempts. No provider or strategy gate was silently substituted. External account/provider availability remains outstanding. |
| Empty UW optional features and missing earnings dates produced misleading parsing failures. | Report empty observations as unavailable and skip missing earnings dates. Regression tests distinguish missing observations from neutral scores. |
| Confirmed market entries used their purchase reference as the breakout pivot, causing premature failed-breakout exits and possible re-entry. | Recover the original pivot from the frozen setup plan when adopting or reloading a position. Preserve execution prices and protective stops. Regression tests verify that a pullback above the setup pivot stays open while an actual failure below it exits. This agrees with the backtest's existing use of `sig.pivot`. |

## Broker paper exercises

All deliberate trades used an IBKR DU paper account, a separate API client and isolated state outside the strategy's learning journal. SPY was verified flat and without existing orders before each run.

The successful end-to-end exercise at approximately 16:17 UTC verified:

1. One-share stop-limit bracket acknowledged, cancelled and recovered as cancelled after reconnect.
2. Three-share SPY market entry, filled at 780.51, with a one-share OCO target/stop and a two-share protective stop.
3. Reconnect with the same open quantity and protective order identities.
4. Deliberately marketable target filled one share; the OCO sibling cancelled.
5. Deliberately triggered protective stop sold the remaining two shares.
6. Full close reconciled with known commissions; reported test P&L was -2.98 USD.
7. Another reconnect did not duplicate journal records; SPY was flat with no residual orders and unrelated positions unchanged.

Earlier attempts also tested the failure path: one exposed immutable SDK commission handling, and one deliberately aggressive test limit was rejected by IBKR's price constraint. Both were cleaned up to flat before retrying. Forced test outcomes are excluded from strategy training.

After the isolated test, a normal strategy pass closed the existing 194-share ILMN position under its `failed_breakout` rule. Actual exit average was 275.2467, commissions were known, and journal P&L was -1,654.68 USD. A separate account read confirmed no remaining positions or open orders at that checkpoint.

That normal pass continued through 64 monitored symbols and opened qualifying paper positions. The next independently read checkpoint matched the journal: CRWD 80, RBRK 494, PANW 102, AMD 95 and FTNT 300 shares, each covered by equal protective-stop quantities. XMTR entered, closed and later re-entered with 207 shares. Reviewing that sequence exposed the incorrect pivot reference above; it was corrected for new and existing managed records without changing stops or rewriting historical fills. These are ordinary strategy trades and remain in its journal; the SPY exercises remain isolated. Scheduled reconciliation recovered after temporary writer-lease contention during the manual audit pass, and the next daemon status showed no task errors.

## Remaining boundaries

The broker's completed-order endpoint can still be unavailable; the application now tolerates that outage using observed evidence instead of freezing. Events missed while disconnected and absent from broker history cannot be reconstructed automatically without another authoritative source. Preserve broker statements and backups.

Configured AI services returned Google quota/service errors, Venice/proxy payment-required responses, and NVIDIA timeout/model-availability errors. Cooldowns reduce disruption but cannot repair external billing, quotas or missing model access. Current reviewer/committee configuration is advisory, with committee veto disabled. Optional Stocktwits access was denied; Reddit credentials were not configured.

Daily bars do not establish intraday order of events, executable fills, spread or queue priority. Intraday shadows skip the uncertain entry-day path and can show large gap losses relative to very tight stops; these estimates need richer replay data and forward validation. Four/five paper outcomes cannot demonstrate strategy improvement. Real-money operation, all-vendor integration validation, external backups and complete visual usability redesign are outside the evidence established by this repair audit.
